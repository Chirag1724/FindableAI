# FindableAI API Reference

This document provides a technical reference for the FindableAI backend REST API and Server-Sent Events (SSE) streaming interfaces. All routes are implemented in [backend/app/api/v1/](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/api/v1/) and mounted under the `/api/v1` prefix.

---

## Global API Standards

### Base URLs & Aliases
- **Primary API Base:** `/api/v1` (e.g. `http://localhost:8000/api/v1`)
- **Compatibility Alias:** `/api/scans` is mounted alongside `/api/v1/scans` to preserve Contract 2 interoperability.
- **Root Metadata:** `GET /` provides service status and API version metadata.
- **Interactive Documentation:** `/docs` (Swagger UI) and `/redoc` (ReDoc).

### Authentication & Authorization
Authentication is configured via `settings.API_KEY` in [backend/app/core/config.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/core/config.py):
- **Development / Default:** When `API_KEY` is empty, authentication is optional and bypasses checks.
- **Enforced Mode:** When `API_KEY` is set to a non-empty string, all mutating endpoints (`POST /api/v1/scans`, `POST /api/v1/scans/{id}/patches/apply`, `POST /api/v1/patches/apply-pr`) require one of the following request headers:
  - `X-API-Key: <configured_api_key>`
  - `Authorization: Bearer <configured_api_key>`
- **Unauthorized Response:** Returns `HTTP 401 Unauthorized` with detail `"Invalid or missing API key"`.

### Rate Limiting
In-memory sliding-window rate limiting is implemented in [backend/app/core/rate_limiter.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/core/rate_limiter.py):
- **Scan Creation:** Limited to `RATE_LIMIT_SCANS_PER_MINUTE` (default: 10 requests per minute per IP).
- **Mutating Operations:** Limited to `RATE_LIMIT_REQUESTS_PER_MINUTE` (default: 60 requests per minute per IP).
- **Rate Limit Exhaustion:** Returns `HTTP 429 Too Many Requests` with a `Retry-After: 60` response header.

### Security Headers & Request Tracing
Every HTTP response includes standard security and tracing headers generated by middleware in [backend/app/main.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/main.py):
- `X-Request-ID`: Unique UUID tracking the request across server logs.
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`

## Endpoint Catalog

### 1. Health & Readiness Check

#### `GET /api/v1/health`
Performs an active database ping (`SELECT 1`) to determine service health and database connectivity.

- **Authentication:** None required.
- **Rate Limit:** None.
- **Success Status:** `200 OK`
- **Response Model:** `HealthCheckResponse` ([backend/app/api/v1/health.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/api/v1/health.py))

```json
{
  "status": "healthy",
  "service": "FindableAI",
  "version": "0.1.0",
  "database": "connected",
  "environment": "development"
}
```

*Note: If the database is unreachable, `status` returns `"degraded"` and `database` returns `"disconnected"`, while returning `200 OK` so load balancers can inspect the degraded state.*

### 2. Initiate Machine Discoverability Scan

#### `POST /api/v1/scans`
Initiates an asynchronous discovery and evaluation pipeline for the target URL. Validates against SSRF attack vectors, persists the record, and schedules the background crawler DAG.

- **Authentication:** Required if `API_KEY` is configured.
- **Rate Limit:** Governed by `RATE_LIMIT_SCANS_PER_MINUTE`.
- **Success Status:** `202 Accepted`
- **Request Model:** `ScanRequest` ([backend/app/schemas/scan.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/schemas/scan.py))

```json
{
  "url": "https://bistro-demo.example.com",
  "max_pages": 5,
  "personas": ["cto", "developer", "procurement"],
  "repo_url": "https://github.com/acme/bistro-site"
}
```

- **Response Model:** `ScanResponse`

```json
{
  "scan_id": "scan_ba38d45a981a",
  "target_url": "https://bistro-demo.example.com",
  "status": "pending",
  "created_at": "2026-10-04T12:00:00.000000Z",
  "completed_at": null,
  "f_score": null,
  "summary": null,
  "patches": [],
  "intents": [],
  "contradictions": [],
  "error": null,
  "execution_mode": null,
  "llm_calls_made": 0,
  "repo_url": "https://github.com/acme/bistro-site",
  "github_repo_url": "https://github.com/acme/bistro-site"
}
```

- **Error Codes:**
  - `400 Bad Request`: SSRF security validation failure (private subnet, loopback IP, AWS metadata IP, or non-HTTP scheme).
  - `401 Unauthorized`: Missing or invalid API key.
  - `429 Too Many Requests`: Rate limit exceeded.

### 4. Stream Scan Progress (Server-Sent Events)

#### `GET /api/v1/scans/{scan_id}/stream`
Provides a live Server-Sent Events (SSE) feed emitting progress percentages, current DAG execution steps, and completion events. Automatically sends keepalive heartbeats (`: heartbeat\n\n`) every 30 seconds.

- **Authentication:** None required.
- **Media Type:** `text/event-stream`
- **Stream Event Payload:** `ScanStatusEvent` ([backend/app/schemas/scan.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/schemas/scan.py))

```text
data: {"scan_id": "scan_ba38d45a981a", "status": "crawling", "progress_percent": 15, "current_step": "Crawling Pages", "message": "Discovered 4 route URLs...", "timestamp": "2026-10-04T12:00:05.123456Z"}

data: {"scan_id": "scan_ba38d45a981a", "status": "synthesizing_intents", "progress_percent": 45, "current_step": "Synthesizing Intents", "message": "Generating 30 buyer queries via LLM...", "timestamp": "2026-10-04T12:00:15.654321Z"}
```

### 9. Apply Remediation Patches via GitHub PR

#### `POST /api/v1/scans/{scan_id}/patches/apply`
Autonomous PR engine endpoint. Creates a Git branch, injects patches or commits a markdown remediation guide (`docs/FINDABLE_AI_REMEDIATION.md`), and opens a Pull Request against the target repository.

- **Authentication:** Required if `API_KEY` is configured.
- **Rate Limit:** Governed by `RATE_LIMIT_REQUESTS_PER_MINUTE`.
- **Success Status:** `200 OK`
- **Request Body (Optional):**

```json
{
  "repo_url": "https://github.com/acme/bistro-site",
  "target_branch": "main"
}
```

- **Response Model:** `PullRequestResult` ([backend/app/schemas/patch.py](file:///c:/Users/LENOVO/Desktop/FindableAI/backend/app/schemas/patch.py))

```json
{
  "pr_url": "https://github.com/acme/bistro-site/pull/12",
  "pr_number": 12,
  "branch_name": "findableai/remediation/scan_ba38d45a981a",
  "title": "FindableAI: Machine Discoverability Remediation Patches (scan_ba38d45a981a)",
  "created_at": "2026-10-04T12:01:10.000000Z"
}
```

- **Execution Behaviors:**
  - **Direct Push:** If the authenticated token owns the repo or has write access, creates the branch directly on the target repo without forking.
  - **Fork Fallback:** If direct push access is absent, automatically creates or reuses a personal fork.
  - **Framework Route Fallback:** If the target repository uses a component framework (`.tsx`, `.jsx`, `.vue`, `.astro`), commits complete instructions to `docs/FINDABLE_AI_REMEDIATION.md` to avoid JSX corruption.
  - **Idempotency:** If an open PR already exists for the branch, reuses the existing PR number and URL.

### 10. Single Patch PR Delegation

#### `POST /api/v1/patches/apply-pr`
Delegates single-patch PR creation directly to the unified `apply_scan_patch` pipeline.

- **Authentication:** Required if `API_KEY` is configured.
- **Success Status:** `200 OK`
- **Request Model:**

```json

  "patch_id": "patch_e3f9a1b2",
  "github_repo_url": "https://github.com/acme/bistro-site",
  "target_branch": "main"
}
```

- **Response Model:** `PullRequestResult`

## Execution Modes & Fallback Boundaries

| Feature | Real Execution (`real_llm`) | Deterministic Fallback (`deterministic_fallback`) |
| :--- | :--- | :--- |
| **Crawl Engine** | Headless Playwright Chromium extracting full rendered DOM. | Fallback to `httpx` + `BeautifulSoup` if browser binary unavailable. |
| **Intent Generation** | Groq LPU (`qwen/qwen3.8-27b`) structured Pydantic schema generation. | Deterministic 30-query heuristic generator across 10 commercial categories. |
| **NLI & Contradictions** | Semantic embedding cosine similarity + LLM entailment verification. | Heuristic keyword & regex pattern extraction. |
| **Scoring Formula** | Canonical mathematical formula: `0.40*S_ans + 0.30*S_con + 0.20*S_str + 0.10*S_acc`. | Identical mathematical formula applied to heuristic evaluations. |
| **Patch Generation** | Schema.org JSON-LD generation with precise DOM anchor injection. | Template-based standard Schema.org structures. |
| **GitHub PR Engine** | Live PyGithub client pushing commits and opening real pull requests. | Live PyGithub client pushing commits and opening real pull requests. |
