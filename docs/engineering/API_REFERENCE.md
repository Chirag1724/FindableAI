# FindableAI API Reference

This document provides a technical reference for the FindableAI backend REST API and Server-Sent Events (SSE) streaming interfaces. All routes are implemented in [backend/app/api/v1/](../../backend/app/api/v1/) and mounted under the `/api/v1` prefix.

---

## Global API Standards

### Base URLs & Aliases
- **Primary API Base:** `/api/v1` (e.g. `http://localhost:8000/api/v1`)
- **Compatibility Alias:** `/api/scans` is mounted alongside `/api/v1/scans` to preserve Contract 2 interoperability.
- **Root Metadata:** `GET /` provides service status and API version metadata.
- **Interactive Documentation:** `/docs` (Swagger UI) and `/redoc` (ReDoc).

### Authentication & Authorization
Authentication is configured via `settings.API_KEY` in [backend/app/core/config.py](../../backend/app/core/config.py):
- **Development / Default:** When `API_KEY` is empty, authentication is optional and bypasses checks.
- **Enforced Mode:** When `API_KEY` is set to a non-empty string, all mutating endpoints (`POST /api/v1/scans`, `POST /api/v1/scans/{id}/patches/apply`, `POST /api/v1/patches/apply-pr`) require one of the following request headers:
  - `X-API-Key: <configured_api_key>`
  - `Authorization: Bearer <configured_api_key>`
- **Unauthorized Response:** Returns `HTTP 401 Unauthorized` with detail `"Invalid or missing API key"`.

### Rate Limiting
In-memory sliding-window rate limiting is implemented in [backend/app/core/rate_limiter.py](../../backend/app/core/rate_limiter.py):
- **Scan Creation:** Limited to `RATE_LIMIT_SCANS_PER_MINUTE` (default: 10 requests per minute per IP).
- **Mutating Operations:** Limited to `RATE_LIMIT_REQUESTS_PER_MINUTE` (default: 60 requests per minute per IP).
- **Rate Limit Exhaustion:** Returns `HTTP 429 Too Many Requests` with a `Retry-After: 60` response header.

### Security Headers & Request Tracing
Every HTTP response includes standard security and tracing headers generated by middleware in [backend/app/main.py](../../backend/app/main.py):
- `X-Request-ID`: Unique UUID tracking the request across server logs.
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Referrer-Policy: strict-origin-when-cross-origin`

## Endpoint Catalog

### 1. Health & Readiness Check

#### `GET /api/v1/health`
Performs an active database ping (`SELECT 1`) to determine service health and database connectivity.

- **Authentication:** None required.
- **Rate Limit:** None.
- **Success Status:** `200 OK`
- **Response Model:** `HealthCheckResponse` ([backend/app/api/v1/health.py](../../backend/app/api/v1/health.py))

```json
{
  "status": "healthy",
  "service": "FindableAI",
  "version": "0.1.0",
  "database": "connected",
  "environment": "development"
}
```

*Note: If the database is unreachable, `status` returns `"degraded"` and `database` returns `"disconnected"`, while returning `200 OK` so load balancers can inspect the degraded state.*

### 2. Initiate Machine Discoverability Scan

#### `POST /api/v1/scans`
Initiates an asynchronous discovery and evaluation pipeline for the target URL. Validates against SSRF attack vectors, persists the record, and schedules the background crawler DAG.

- **Authentication:** Required if `API_KEY` is configured.
- **Rate Limit:** Governed by `RATE_LIMIT_SCANS_PER_MINUTE`.
- **Success Status:** `202 Accepted`
- **Request Model:** `ScanRequest` ([backend/app/schemas/scan.py](../../backend/app/schemas/scan.py))

```json
{
  "url": "https://bistro-demo.example.com",
  "max_pages": 5,
  "personas": ["cto", "developer", "procurement"],
  "repo_url": "https://github.com/acme/bistro-site"
}
```

- **Response Model:** `ScanResponse`

```json
{
  "scan_id": "scan_ba38d45a981a",
  "target_url": "https://bistro-demo.example.com",
  "status": "pending",
  "created_at": "2026-10-04T12:00:00.000000Z",
  "completed_at": null,
  "f_score": null,
  "summary": null,
  "patches": [],
  "intents": [],
  "contradictions": [],
  "error": null,
  "execution_mode": null,
  "llm_calls_made": 0,
  "repo_url": "https://github.com/acme/bistro-site",
  "github_repo_url": "https://github.com/acme/bistro-site"
}
```

- **Error Codes:**
  - `400 Bad Request`: SSRF security validation failure (private subnet, loopback IP, AWS metadata IP, or non-HTTP scheme).
  - `401 Unauthorized`: Missing or invalid API key.
  - `429 Too Many Requests`: Rate limit exceeded.

### AI Website Health Brief (on-demand AI Summary)

> **Canonical deep dive:** [AI_WEBSITE_HEALTH_BRIEF.md](AI_WEBSITE_HEALTH_BRIEF.md).  
> Do **not** confuse with the `summary` object on `GET /api/v1/scans/{id}` (crawl/stats `AuditSummary`).

#### `GET /api/v1/scans/{scan_id}/summary`
Returns the cached brief for the current grounded input hash, or `status: "none"` if no ready row exists. **Does not call the LLM.**

- **Auth:** Scans router `verify_api_key` + `OrgAction.READ_SCANS` (see Health Brief doc).
- **Alias:** `/api/scans/{scan_id}/summary`
- **Body:** none
- **Success:** `200 OK` with `SummaryResponse` (`status` may be `none` or `ready`)
- **Errors:** `401` / `403` / `404`

#### `POST /api/v1/scans/{scan_id}/summary`
Generates a grounded Website Health Brief or returns an existing cache hit. Outside the per-scan `MAX_LLM_CALLS_PER_SCAN` budget.

- **Auth:** Same as GET (`READ_SCANS`)
- **Alias:** `/api/scans/{scan_id}/summary`
- **Body:** none
- **Response model:** `SummaryResponse` ([backend/app/schemas/summary.py](../../backend/app/schemas/summary.py))

| HTTP | `status` | Typical `reason` |
| :--- | :--- | :--- |
| `200` | `ready` | Cache hit or fresh generation (`cached` true/false) |
| `202` | `generating` | `summary_generating` |
| `409` | `none` | `scan_queued` / `scan_running` / `scan_failed` / `scan_cancelled` / `scan_ineligible` |
| `429` | `failed` | `summary_rate_limited` (+ `retry_after`) |
| `502` | `failed` | `summary_generation_failed` / `provider_auth_error` / `provider_model_rejected` |

```bash
# Inspect cache (no LLM)
curl -sS -H "X-API-Key: YOUR_API_KEY" \
  "http://localhost:8000/api/v1/scans/SCAN_ID/summary"

# Generate or return cached brief
curl -sS -X POST -H "X-API-Key: YOUR_API_KEY" \
  "http://localhost:8000/api/v1/scans/SCAN_ID/summary"
```

### 9. Apply Remediation Patches via GitHub PR

#### `POST /api/v1/scans/{scan_id}/patches/apply`
Autonomous PR engine endpoint. Creates a Git branch, injects patches or commits a markdown remediation guide (`docs/FINDABLE_AI_REMEDIATION.md`), and opens a Pull Request against the target repository.

- **Authentication:** Required if `API_KEY` is configured.
- **Rate Limit:** Governed by `RATE_LIMIT_REQUESTS_PER_MINUTE`.
- **Success Status:** `200 OK`
- **Request Body (Optional):**

```json
{
  "repo_url": "https://github.com/acme/bistro-site",
  "target_branch": "main"
}
```

- **Response Model:** `PullRequestResult` ([backend/app/schemas/patch.py](../../backend/app/schemas/patch.py))

```json
{
  "pr_url": "https://github.com/acme/bistro-site/pull/12",
  "pr_number": 12,
  "branch_name": "findableai/remediation/scan_ba38d45a981a",
  "title": "FindableAI: Machine Discoverability Remediation Patches (scan_ba38d45a981a)",
  "created_at": "2026-10-04T12:01:10.000000Z"
}
```

- **Execution Behaviors:**
  - **Direct Push:** If the authenticated token owns the repo or has write access, creates the branch directly on the target repo without forking.
  - **Fork Fallback:** If direct push access is absent, automatically creates or reuses a personal fork.
  - **Framework Route Fallback:** If the target repository uses a component framework (`.tsx`, `.jsx`, `.vue`, `.astro`), commits complete instructions to `docs/FINDABLE_AI_REMEDIATION.md` to avoid JSX corruption.
  - **Idempotency:** If an open PR already exists for the branch, reuses the existing PR number and URL.

## Execution Modes & Fallback Boundaries

Modes are set in `backend/app/api/v1/scans.py` after DAG execution. Canonical product semantics: [LIMITATIONS_AND_READINESS.md](LIMITATIONS_AND_READINESS.md).

| Mode value | When set | Meaning |
| :--- | :--- | :--- |
| `real_llm` | Non-empty evaluations **and** `llm_calls_made > 0` | At least one budgeted LLM provider call ran successfully. |
| `deterministic` | Not `real_llm` and `ENVIRONMENT=production` | Production label for non-real path. |
| `synthetic_fallback` | Not `real_llm` and non-production | Dev label when LLM path did not count provider calls. |

| Feature | Real Execution (`real_llm`) | Synthetic / mock fallback (non-`real_llm`) |
| :--- | :--- | :--- |
| **Crawl Engine** | Playwright (httpx fallback if needed). | Same crawl path — crawl does not require LLM. |
| **Intent Generation** | `IntentGenerator` → structured `IntentBatch` (30 queries). | `_generate_fallback_evaluations` templates if DAG returns no evaluations. |
| **Evidence selection** | Prefer hybrid dense+lexical+RRF; first-*k* OBSERVE only when empty. | Same or empty depending on stage failure. |
| **NLI & Contradictions** | LLM entailment + contradiction detector when stages succeed. | Optional `_generate_fallback_contradictions` if DAG error and empty list. |
| **Scoring Formula** | Deterministic: `0.40*S_ans + 0.30*S_con + 0.20*S_str + 0.10*S_acc` (components 0–100; **no** outer ×100). | Same formula on synthetic inputs, **or** `generate_mock_fscore` in non-prod if scorer returns None. |
| **Patch Generation** | `assemble_real_patches` when score breakdown exists. | `generate_mock_patches` in non-prod if assembly returns `None`; prod uses `[]`. |
| **GitHub PR Engine** | Separate apply endpoint; requires `GITHUB_TOKEN`. Not part of default scan DAG (`create_pr=False`). | Same — PR is not auto-run on scan complete. |

**Do not** treat synthetic intents, mock F-scores, or mock patches as proof of a successful real-LLM audit.
